### Poppler CVE-2025-52885 evidence update

The official Debian tracker lists Bullseye fixed at `20.09.0-3.1+deb11u3`, Bookworm fixed at `22.12.0-2+deb12u2`, and Trixie fixed at `25.03.0-5+deb13u3`; these public targets do not need a GetPatched backport. It identifies upstream commit [`4ce27cc826bf90cc8dbbd8a8c87bd913cccd7ec0`](https://gitlab.freedesktop.org/poppler/poppler/-/commit/4ce27cc826bf90cc8dbbd8a8c87bd913cccd7ec0), which rejects duplicate number-tree keys before the vulnerable vector is resized. GitHub Security Lab's public PoC says `pdfinfo -struct bug.pdf` crashes on the vulnerable build. The fixture, its MIT license, and the exact Focal source archives were fetched and hash-checked. On pristine source, an AppleClang AddressSanitizer build reproduces `heap-use-after-free` in `StructTreeRoot::parentTreeAdd`; the same source with the local backport exits 0 without an ASan finding. Raw logs are retained in `evidence/poppler-cve-2025-52885-source-regression-20261030/`. The recipe at `../packaging-poppler/` is still an unreleased development candidate: Ubuntu package builds, installed-package regressions, package-aware scans, and signed client checks remain outstanding.

No arm64 target is selected at preflight. It can be added only after the full native/appropriate cross-build, scan, regression and signed client installation succeed. Current platform routing is verified only for Ubuntu Focal amd64; Debian targets need the platform build and public repository path implemented and verified before any Debian release.

## Libpng CVE-2025-65018 reproduction status

The Focal source is confirmed to be pristine upstream `1.6.37` before GetPatched patches. The CVE patch applies, and the separate CVE-2026-22801 write-stride regression reproduces on the vulnerable native build and passes on the patched build. CVE-2025-65018 is not yet reproduced: the upstream issue's attached 286-byte PNG has IHDR interlace method `0`, despite the report describing an interlaced PNG. Its sample harness also leaves the simplified API's 16-bit default output selected while allocating only four bytes per pixel. A guarded 8-bit RGBA read using that image and a separately generated valid Adam7 image both completed on the pristine 1.6.37 build without changing the output guard. A native AddressSanitizer build likewise did not produce the claimed overflow for these inputs. This does not disprove the CVE, but it means the current package regression fixture is inadequate and the Focal libpng candidate must not be marked verified or released until a valid baseline reproducer and patched regression are established.

The requested CVE-2026-22695 follow-up was checked against the exact Focal source and the complete upstream history. Debian's tracker identifies commit `218612ddd6b17944e21eda56caf8b4bf7779d1ea` as introducing it, and commit `e4f7ad4ea2a471776c81dda4846b7691925d9786` as fixing it. The correct CVE-2025-65018 solution is the final 218612d rearchitecture, not preliminary commit 16b5e38; therefore 22695 must be assessed as part of the same backport and cannot be dismissed merely because Focal 1.6.37 lacks the new function today. The prior upstream issue's attached sample/harness does not faithfully reproduce the claimed overflow; baseline reproduction on the exact installed Focal package remains required before this target can be released.

## Security-impact qualification for TIFF

The current official tracker records CVE-2025-61143 as a null-pointer crash in `tiffcrop`, and CVE-2025-61144 as a stack-based buffer overflow in `tiffcrop`'s `readSeparateStripsIntoBuffer`. Exact Focal, Bookworm, and Trixie sources exit immediately after the identified `loadImage` failure, before the cleanup code fixed by the 61143 patch; our malformed-input source build did not reproduce 61143, so it is excluded pending a valid target-specific reproducer. CVE-2025-61144 reproduces in source builds. Debian describes the CLI crash as having no security impact; Ubuntu assigns Low priority despite CVSS 7.3. This does not support presenting TIFF as a remote library vulnerability or implying demonstrated code execution. The target remains conditional on reproducing the issue in exact installed `tiff-tools` packages and observing the upstream regression pass.
